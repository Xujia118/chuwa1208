**Explain how brokers work with topics**


brokers and topics work together to store and distribute data in a scalable way.

A broker is simply a Kafka server. It is responsible for receiving messages from producers, storing them on disk, and serving them to consumers. A Kafka cluster usually has multiple brokers to provide scalability and fault tolerance.

A topic is a logical category or stream of data (for example, orders, payments, logs). However, a topic is not stored in just one place. Instead, each topic is split into multiple partitions, and those partitions are distributed across different brokers in the cluster.

Here’s how they work together:

- When you create a topic with multiple partitions, Kafka distributes those partitions across brokers.

- Each partition physically lives on exactly one broker as its leader.

- For fault tolerance, partitions can have replicas stored on other brokers.

- Producers send messages to a specific topic partition (usually determined by key hashing).

- The broker that holds the leader of that partition receives and stores the message.

- Consumers read from the leader partition on the corresponding broker.
