**Are messages pushed to consumers or consumers pull messages from topics?**

consumers pull messages from brokers — messages are not pushed to them.

Kafka uses a pull-based model. Consumers actively send fetch requests to the broker to retrieve messages from specific topic partitions. The broker simply stores data and responds when a consumer asks for it. This design gives consumers control over how fast they process data, since they decide when and how much to fetch.

One major advantage of the pull model is backpressure handling. If a consumer is slow, it can fetch smaller batches or poll less frequently. If it is fast, it can request larger batches. In a push system, the broker would have to guess the consumer’s capacity, which could overwhelm slower consumers.

Another benefit is efficient batching. Consumers can request multiple messages in one fetch request, reducing network overhead and improving throughput.
