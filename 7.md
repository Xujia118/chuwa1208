**Explain consumer lag and how to resolve it**

Consumer lag refers to the difference between the latest offset in a partition (the “log end offset”) and the offset that a consumer group has committed. In simple terms, it measures how far behind a consumer is from real-time data production. If producers are writing messages faster than consumers can process them, lag increases.

Consumer lag happens for several common reasons. The most frequent cause is slow processing logic — for example, heavy database writes, external API calls, or CPU-intensive computation inside the consumer. It can also occur if there are too few consumers relative to partitions, insufficient hardware resources (CPU, memory, network I/O), frequent rebalances, or inefficient batch sizes and polling configurations. Sometimes lag spikes temporarily during traffic bursts.

High consumer lag does not mean data loss, but it can cause delayed processing, SLA violations, and eventually message expiration if the retention period is reached before consumption.

There are several ways to resolve consumer lag. One approach is scaling horizontally by adding more consumers to the consumer group — but only up to the number of partitions, since parallelism is limited by partitions. Another solution is to optimize processing logic (e.g., batch database writes, use async I/O, reduce blocking calls), increase fetch sizes, tune poll configurations, or improve hardware resources.
