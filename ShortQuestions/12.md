**12. Explain bearer token and how JWT works.**

Bearer Token

A Bearer token is an access token that proves authorization by possession.

*Whoever bears (has) the token is treated as the authenticated user.*

In HTTP, it’s usually sent in the Authorization header:

```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

```

Key properties

- No session state on the server (stateless)

- No extra proof required (no password, no signature per request)

- If stolen → attacker can use it

- Must be protected by HTTPS (TLS)


JWT token

A JWT has three parts, separated by dots:

```
header.payload.signature

Example:

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
.eyJzdWIiOiIxMjMiLCJ1c2VybmFtZSI6ImppYSIsImV4cCI6MTcwMDAwMDAwMH0
.5x8QyQxJw...

```

Workflow

1. Client sends credentials to log in
2. Server validates credentials, issues jwt and sends it back in Authorization header
3. In all subsequent requests, client browser will include jwt in Authorization header
4. Server verifiges client jwt by running algorith again, no db calls
