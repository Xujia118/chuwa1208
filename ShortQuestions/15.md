**15. What is the disadvantage of Session? How to overcome the disadvantage?**

Disadvantages of Session

1. Server Memory Usage

- Sessions are stored on the server, typically in RAM.

- Each user consumes memory, so if you have thousands or millions of users, the server can run out of memory.

- This makes scaling horizontally (adding more servers) tricky because session data needs to be shared.

2. Scalability Issues

- If your app runs on multiple servers, a user’s session must be available to all servers.

- Without special handling, you can get “lost session” errors if the request hits a different server.

3. Persistence

- Sessions are temporary. If the server restarts, sessions stored in memory are lost unless you use a persistent store.

4. Security Risks

- Session IDs can be stolen (session hijacking).

- You need to implement measures like HTTPS, HttpOnly cookies, and session expiration.

5. Maintenance Overhead

- You may need to clean up expired sessions to free server memory.


How to Overcome These Disadvantages

1. Use a Distributed Cache for Sessions

- Instead of storing sessions in server memory, use Redis, Memcached, or database-backed sessions.

- This allows horizontal scaling and persistence across server restarts.

2. Stateless Authentication

- Use JWT (JSON Web Tokens) or other token-based authentication.

- The server doesn’t need to store any session data; the client carries all required info.

- This improves scalability and reduces server memory usage.

3. Session Expiration and Cleanup

- Set appropriate timeouts and automatic cleanup of expired sessions.

- Sticky Sessions (less preferred)

    - In load-balanced setups, configure sticky sessions so the same user always hits the same server.

    - Works for small setups but not ideal for large-scale apps.
