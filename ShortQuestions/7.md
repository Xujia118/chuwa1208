**In the Raft consensus algorithm, why does a candidate need its log to be at least as up-to-date as the majority of the cluster in order to win an election? What safety property does this guarantee?**

Imagine this bad scenario without the rule:

- Old leader L1 successfully replicated a command X to a majority.

- Before L1 tells everyone, it crashes.

- A node C that does not have X becomes leader.

- C overwrites logs on other nodes.

- Command X — which was already committed — disappears.

That would be catastrophic. A client was told “your operation is committed,” and later the system forgets it.

By requiring:

“Only a candidate whose log is at least as up-to-date as a majority can win”

Raft ensures:

Leader Completeness Property

If a log entry is committed in term T, then every leader elected in a later term must contain that entry.

Why this works:

- A committed entry exists on a majority of nodes.

- A candidate must collect votes from a majority.

- At least one voter must already have that committed entry.

- That voter will refuse to vote for any candidate whose log is missing it.

- Therefore, a candidate missing committed entries cannot win.
