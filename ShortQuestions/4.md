**What are the four necessary conditions for a deadlock to occur? Explain how "lock ordering" prevents deadlock.**

- Deadlock

For a deadlock to happen, four necessary conditions—known as the Coffman conditions—must all be present at the same time.

The first condition is mutual exclusion. At least one resource must be non-shareable, meaning only one thread can use it at a time. For example, a lock protecting a critical section or a database row lock can only be held by one thread. If resources were freely shareable, deadlock would not occur because no thread would have to wait.

The second condition is hold and wait. A thread must be holding at least one resource while simultaneously waiting to acquire additional resources held by other threads. For instance, Thread A holds Lock 1 and waits for Lock 2, while still retaining Lock 1. This partial holding of resources creates the potential for circular dependencies.

The third condition is no preemption. Resources cannot be forcibly taken away from a thread; they must be released voluntarily. In most lock-based synchronization systems (like synchronized blocks or ReentrantLock in Java), a lock cannot simply be revoked by the system—it must be explicitly unlocked by the thread that owns it. If preemption were allowed, the system could break deadlocks by taking resources away.

The fourth condition is circular wait. There must be a circular chain of threads where each thread waits for a resource held by the next thread in the cycle. For example, Thread A waits for a resource held by Thread B, Thread B waits for one held by Thread C, and Thread C waits for one held by Thread A. This circular dependency is what makes the deadlock permanent.

- Lock ordering 

Lock ordering prevents deadlock by eliminating the circular wait condition. The idea is to impose a global, consistent ordering on resource acquisition. Every thread must acquire locks in the same predefined order. For example, suppose we assign Lock A an order value of 1 and Lock B an order value of 2. All threads must always acquire Lock A before Lock B. No thread is allowed to acquire Lock B and then attempt to acquire Lock A. Because all threads follow the same order, it becomes impossible to form a circular dependency. A thread might still wait, but the wait graph can never form a cycle, so deadlock cannot occur.
