**4. list all http status codes that related to authentication and authorization failures.**

401 Unauthorized (Authentication failure)

When to use

- Missing token

- Invalid / expired JWT

- Bad username/password

- No authentication provided at all

403 Forbidden (Authorization failure)

Client is authenticated, but does not have permission.

When to use

- Valid JWT but insufficient role (USER accessing ADMIN)

- User tries to access someone else’s resource

- Access denied by ACL / policy


400 Bad Request (Auth-related misuse)

Not an auth error by definition, but commonly used when:

- Malformed token

- Invalid auth header format

404 Not Found (Security-through-obscurity pattern)

Sometimes returned instead of 403 to:

- Hide existence of a protected resource

409 Conflict (Auth flow edge cases)

Occasionally used in auth flows:

- Account locked

- Duplicate registration

- Session conflict


Summary table:

| Status  | Meaning           | Use Case                        |
| ------- | ----------------- | ------------------------------- |
| **401** | Not authenticated | Missing / invalid credentials   |
| **403** | Not authorized    | Authenticated but no permission |
| 400     | Bad request       | Malformed auth input            |
| 404     | Not found         | Hide resource existence         |
| 407     | Proxy auth        | Proxy authentication            |
| 409     | Conflict          | Auth state conflict             |
| 419     | Session expired   | Framework-specific              |
| 423     | Locked            | Account/resource locked         |
