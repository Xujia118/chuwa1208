**4. Compare Spring AOP vs Java Reflection vs Spring Interceptor.**

Spring AOP (Aspect-Oriented Programming)

- Spring AOP is a "higher-level" abstraction designed specifically to manage "cross-cutting concerns"—logic that is repeated across many parts of your app (like logging or security).

- How it works: It creates proxies (using JDK Dynamic Proxies or CGLIB). When you call a method on a bean, you’re actually calling the proxy, which executes your "Advice" (the AOP logic) before or after the real method.

- Best For: Service-layer logic. Common examples include @Transactional management, logging method execution times, or custom security checks on specific service methods.

- Cons: It only works on Spring-managed Beans. By default, it cannot intercept internal method calls within the same class (because the proxy is bypassed).

Java Reflection

- Reflection is the foundation upon which many frameworks (including Spring) are built. It allows a program to "look in the mirror" and inspect its own structure.

- How it works: It uses the java.lang.reflect API to browse class metadata and invoke methods or access fields at runtime, even if they are private.

- Best For: Writing generic frameworks, libraries, or tools (like a JSON serializer or a dependency injection container).

- Cons: It is slow because the JVM cannot optimize the code at compile time. It also breaks encapsulation, making code harder to debug and maintain.

Spring Interceptor (HandlerInterceptor)

- Interceptors are a specialized feature of the Spring MVC framework. They sit between the DispatcherServlet and your @Controller.

- How it works: It provides three main hooks: preHandle, postHandle, and afterCompletion. It has access to the HttpServletRequest and HttpServletResponse objects.

- Best For: Web-specific concerns. Examples include checking if a user is logged in (session check), adding common headers to every response, or internationalization (changing the language based on a URL parameter).

- Cons: It only knows about web requests. It cannot intercept a call from one service to another service.

When to use which?

Use Spring Interceptor if your logic is strictly about HTTP requests (e.g., checking a JWT token in a header or logging the IP address of every visitor).

Use Spring AOP if your logic is about Business Logic (e.g., you want to log every time a "Delete" method is called in your database service, regardless of whether it came from a web request or a background task).

Use Java Reflection only if you are building your own framework or need to do something highly dynamic that Spring's built-in tools don't support (e.g., automatically mapping fields from one unknown class to another).
