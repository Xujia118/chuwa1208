**Compare the three caching patterns: Cache-Aside, Write-Through, and Write-Behind. What are the trade-offs of each?**

Cache-Aside (Lazy Loading) is the most common caching pattern. The application first checks the cache; on a miss, it reads from the database, stores the result in the cache, and returns it. Writes typically go directly to the database, and the cache entry is either invalidated or updated separately. This pattern is simple and gives the application full control over what gets cached, reducing unnecessary cache usage. However, it introduces cache-miss latency and risks stale data if invalidation is not handled correctly. It works well for read-heavy workloads where occasional staleness is acceptable.

Write-Through updates the cache and the database synchronously on every write. The application writes to the cache, and the cache immediately writes to the database. This ensures strong consistency between cache and database and avoids stale reads. The trade-off is higher write latency, since each write must complete in both layers before returning. It also increases write load, even for data that may never be read again. This pattern suits systems requiring strong consistency and predictable reads.

Write-Behind (Write-Back) writes data to the cache first and asynchronously persists it to the database later, often in batches. This significantly improves write performance and reduces database load, making it suitable for high-throughput systems. However, it introduces durability risks: if the cache crashes before flushing to the database, data may be lost. It also complicates consistency guarantees, since the database may temporarily lag behind the cache. This pattern is ideal when write performance is critical and some risk or eventual consistency is acceptable.
