**2. Explain TLS, PKI, certificate, public key, private key, and signature.**


Public key & Private key (the cryptographic foundation)

These always come as a pair. They are mathematically linked, but you cannot derive the private key from the public key.

Public key

- Can be shared with everyone

- Encrypt data (so only the private key owner can decrypt)

- Verify signatures

Private key

- Must be kept secret

- Decrypt data

- Create digital signatures


Digital Signature (authenticity + integrity)

A digital signature answers two questions:

- Who sent this?

- Was it modified?

How signing works

- Take the data

- Hash it (e.g. SHA-256)

- Encrypt the hash with the private key

- → that encrypted hash is the signature

How verification works

- Receiver hashes the data again

- Decrypts the signature using the public key

- Compares hashes

- If they match → authentic + unmodified

Certificate (binds identity ↔ public key)

A certificate answers:

“Whose public key is this?”

What a certificate contains

- Public key

- Identity info (domain name, org, etc.)

- Validity period

- Issuer (CA)

- CA’s digital signature

```
Example:

This public key belongs to https://example.com
Signed by: Let's Encrypt

So instead of trusting the website, you trust the Certificate Authority (CA).
```

PKI (Public Key Infrastructure)

PKI is the entire trust system, not a protocol.

It includes:

- Certificate Authorities (CA)

- Root certificates (pre-installed in OS/browser)

- Intermediate certificates

- Certificate revocation (CRL, OCSP)

- Rules & policie

```
Trust chain

Your Browser
  ↓ trusts
Root CA
  ↓ signs
Intermediate CA
  ↓ signs
Website Certificate

```


TLS (Transport Layer Security)

TLS is a protocol that uses everything above to secure network communication.

TLS provides:

- Confidentiality (encryption)

- Authentication (certificates)

- Integrity (signatures / MACs)
