**Kubernetes key concepts**

While Docker runs containers on a single machine, Kubernetes manages containers across a cluster of machines.

A Cluster consists of a Control Plane and multiple Worker Nodes. The control plane makes global decisions (scheduling, scaling, healing), while worker nodes run application workloads.

The smallest deployable unit in Kubernetes is a Pod. A Pod can contain one or more tightly coupled containers that share networking (same IP) and storage. Pods are ephemeral — if one dies, Kubernetes replaces it.

A Deployment defines the desired state for a set of Pods. It enables rolling updates, rollbacks, and scaling. You specify how many replicas you want, and Kubernetes ensures that number is always maintained.

A Service provides stable networking and load balancing for Pods. Since Pods are ephemeral and IPs change, a Service gives a consistent endpoint for internal or external communication.

Kubernetes continuously works toward the desired state declared in configuration files (YAML). If something crashes or drifts from the defined state, Kubernetes automatically reconciles the system back to the desired state.
