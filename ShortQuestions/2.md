**Explain the difference between linearizability and eventual consistency. Give one real-world system example for each.**

1. Linearizability (Strong Consistency)

Definition:

Linearizability guarantees that all operations appear to happen atomically and in some order that respects real-time. That means, once a write completes, any read will see that write or a later one immediately, no matter which node you query.

Key points:

- Strong consistency.

- Operations appear instantaneous (atomic) globally.

- Reads always return the most recent write.

- Makes reasoning about the system simpler, but can hurt availability during network partitions.

Example Real-World System:

Zookeeper: Often used for configuration management or leader election. Zookeeper ensures that clients always see the latest committed value, satisfying linearizability.

2. Eventual Consistency (Weak Consistency)

Definition:

Eventual consistency guarantees that, if no new updates are made, all replicas will eventually converge to the same value. However, reads may return stale data temporarily. There is no immediate guarantee that a read sees the latest write.

Key points:

- Weaker consistency than linearizability.

- Allows high availability and partition tolerance.

- Reads may be stale; updates propagate asynchronously.

- Good for systems prioritizing availability over strict correctness.

Example Real-World System:

Amazon DynamoDB (in eventually consistent mode) or Cassandra: Writes propagate asynchronously. Different nodes may temporarily return different values, but eventually, all replicas converge.
