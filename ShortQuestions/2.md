**2. What is Aspect Oriented Programming, what does "aspect" mean? Explain its use cases in detail?**


AOP is a programming paradigm that supplements Object-Oriented Programming (OOP) by providing another way of thinking about program structure.

In OOP, the key unit of modularity is the class. In AOP, the unit of modularity is the aspect.

AOP allows you to "extract" logic that is used across multiple layers of your application (like logging, security, or transaction management) and keep it in one central place. This prevents code tangling (mixing business logic with infrastructure logic) and code scattering (repeating the same code in every method).

An aspect is the central unit of AOP. It encapsulates:

- A cross-cutting concern (functionality that affects multiple parts of an application)

- The logic needed to implement that concern

- Information about where and when that logic should be executed


Use Cases

A. Transaction Management (The most common use)

When you save a task to the database, you want the entire operation to succeed or fail as a unit.

Without AOP: You’d have to manually write connection.beginTransaction(), session.commit(), and session.rollback() in every service method.

With AOP: You simply add @Transactional. Spring’s Transaction Aspect intercepts the call, starts the transaction, and handles the cleanup.

B. Security and Authorization

Before a user can delete a task, you need to check if they have the ADMIN role.

Use Case: Instead of putting an if (user.isAdmin()) check at the start of every controller method, you use an Aspect (often via @PreAuthorize).

Benefit: The "Business Logic" only cares about how to delete a task, not who is allowed to do it.

C. Logging and Auditing

This is exactly what you did with your LoggingAspect.

Use Case: Tracking which user accessed which API endpoint, or logging the input parameters for debugging.

Benefit: If you want to change the log format from "Plain Text" to "JSON" for a tool like ELK Stack, you change it in one Aspect class rather than 100 Controller methods.

D. Performance Monitoring (Profiling)

You might want to identify "slow" methods in your application.

Use Case: Using @Around advice to start a timer, execute the method, and log the duration.

Benefit: You can toggle this on or off for the entire application (or specific packages) using a single configuration.

E. Exception Handling
While Spring has @ControllerAdvice, that is actually a specialized form of AOP!

Use Case: Catching specific exceptions (like TaskNotFoundException) and converting them into a clean 404 JSON response.

Benefit: Your service methods don't need to be wrapped in giant try-catch blocks; they can just throw the error and let the Aspect handle it.
