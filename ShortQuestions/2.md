**Describe the role of Namespaces and Cgroups in containerization. Provide at least three examples of different namespace types and explain what each one isolates.**

1. What namespaces provide

Namespaces are a Linux kernel feature that give processes the illusion that they are running on their own isolated system. They work by partitioning global system resources so that a process (and its children) can only see and interact with a restricted subset of those resources. From inside a namespace, the process believes it has its own PIDs, network interfaces, mount points, or host identity, even though it is sharing the same kernel with other processes. This isolation is the foundation of containers: instead of virtualizing hardware like a VM, namespaces virtualize views of the OS.

2. What cgroups provide

Cgroups (control groups) are responsible for resource management and accounting, not isolation of views. They let the kernel limit, prioritize, and measure how much CPU, memory, disk I/O, and other resources a group of processes can consume. Without cgroups, a container could see only its own environment (thanks to namespaces) but still monopolize the host’s CPU or exhaust all memory. Cgroups ensure fairness and stability by enforcing hard limits and enabling monitoring and throttling.

3. Examples

PID namespace

The PID (process ID) namespace isolates the process ID number space. Inside a PID namespace, processes see a separate PID hierarchy that starts at 1, meaning a process can believe it is PID 1 (like init) even though it has a different PID on the host. Processes in one PID namespace cannot see or signal processes in another PID namespace unless explicitly allowed. This is why ps inside a container only shows container processes, while the host can still see all of them.

NET namespace

The network (NET) namespace isolates networking resources such as network interfaces, IP addresses, routing tables, firewall rules, and ports. Each container can have its own virtual network stack, appearing to have its own NICs and IP configuration. This allows multiple containers to bind to the same port number (e.g., port 80) without conflict, because each binding occurs in a separate network namespace. Virtual Ethernet pairs (veth) are commonly used to connect container network namespaces to the host or a bridge.

MNT (mount) namespace

The mount (MNT) namespace isolates the filesystem mount table. Processes in different mount namespaces can see different directory trees, mount points, and filesystem layouts. This enables containers to have their own root filesystem (/) without affecting the host or other containers. When a container mounts or unmounts a filesystem, that change is visible only within its mount namespace, which is crucial for providing a clean, container-specific filesystem view.

4. How they work together

Namespaces and cgroups complement each other to form the core of containerization. Namespaces answer the question “What can this process see?” by isolating system views such as processes, networking, and filesystems. Cgroups answer the question “How much can this process use?” by controlling and accounting for resource consumption. Together, they allow containers to feel like independent machines (via namespaces) while remaining safe and efficient on a shared host (via cgroups), all without requiring a separate kernel per container.
