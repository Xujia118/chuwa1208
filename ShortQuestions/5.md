**Describe the quorum condition (W + R > N) in leaderless (Dynamo-style) replication. What happens if this condition is not satisfied?**

1. The quorum condition: $𝑊 + 𝑅 > 𝑁$

In Dynamo-style systems:

N = number of replicas for a given data item (e.g., N = 3)

W = number of replicas that must acknowledge a write for it to be considered successful

R = number of replicas that must respond to a read

The quorum condition is: $𝑊 + 𝑅 > 𝑁$

The logic behind $W + R > N$ is based on the Pigeonhole Principle. If the sum of the nodes you write to and the nodes you read from exceeds the total number of nodes available, there must be at least one node that belongs to both sets.

This "overlap" node acts as the source of truth, ensuring that a read request will always encounter at least one node containing the most recent write.

2. Common Configurations:

$N=3, W=2, R=2$: A balanced setup that can tolerate one node failure for both reads and writes.

$N=3, W=3, R=1$: Optimized for very fast reads, but a single node failure will block all writes.


3. What happens if $W + R \leq N$?

If this condition is not satisfied, the system no longer guarantees strong consistency. Instead, it operates under a model of eventual consistency. Here is what occurs:

- Stale Reads: It becomes mathematically possible to read from a set of nodes ($R$) that does not include any of the nodes where the latest data was written ($W$). You may receive an older version of the data or a "404 Not Found" if the data was new.Read 
- Repair Dependency: The system relies entirely on background processes like "read repair" (fixing stale data when a read eventually finds it) or "anti-entropy" (background Merkle tree syncing) to eventually propagate the data to all nodes.

- Increased Availability: The trade-off is often higher availability and lower latency. By requiring fewer nodes to respond ($W=1, R=1$), the system remains functional even if multiple nodes are down or the network is partitioned, though the risk of returning "garbage" data increases significantly.
