**Explain how container image layers work. What is the copy-on-write mechanism, and why is it important for container efficiency?**

1. Image layer structure

A container image is built as a stack of layers, where each layer represents a filesystem diff produced by an instruction in the image build process (for example, each RUN, COPY, or ADD in a Dockerfile). Instead of being a complete filesystem snapshot, each layer only stores the changes relative to the previous layer—new files, modified files, or deletions (recorded as whiteouts). At runtime, these layers are stacked together using a union filesystem (such as OverlayFS), which presents them as a single coherent filesystem to the container.

2. Read-only vs writable layers

All image layers are immutable and mounted as read-only. When a container is started from an image, the runtime adds a thin writable layer on top of the image layers. Any filesystem changes made by the running container—creating files, modifying files, deleting files—are directed exclusively to this writable layer. The underlying image layers are never modified, which allows them to be safely shared by many containers at the same time.

3. Copy-on-write mechanism

Copy-on-write (CoW) means that when a container attempts to modify a file that exists in a read-only image layer, the storage driver first copies that file into the container’s writable layer and then applies the modification there. Reads continue to come from the original image layer until a write occurs. This avoids eagerly duplicating data: files are only copied when they are actually changed, and unchanged files remain shared across containers.

4. Benefits for storage and performance

This design dramatically improves storage efficiency because identical image layers can be shared across many images and containers without duplication, reducing disk usage and network transfer during pulls. Performance also benefits because container startup is fast—no full filesystem copy is required, just mounting existing layers. Copy-on-write minimizes I/O by copying only modified files, while immutability of image layers improves cacheability, safety, and reproducibility across environments.
