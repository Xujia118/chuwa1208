**What is a CRDT (Conflict-free Replicated Data Type)? Explain how a G-Counter works and why it always converges without coordination.**


Conflict-free Replicated Data Type (CRDT) is a specialized data structure designed to be replicated across multiple nodes in a network. It allows each node to update its local state independently without waiting for "coordination" (like a central lock or consensus) and ensures that all replicas will eventually converge to the exact same state once they receive each other's updates.


A G-Counter is one of the simplest CRDTs. It solves a specific problem: in a distributed system, if two nodes increment a single counter simultaneously, a simple integer addition will result in lost updates because one node's write might overwrite the other's.

Instead of storing a single integer, a G-Counter is represented as an array (or vector) of size $n$, where $n$ is the number of nodes in the system.

- State: Each node $i$ is assigned a specific index in the array $V[i]$.

- Increment: When node $i$ wants to increment the counter, it only increments its own slot $V[i]$. It never touches the slots of other nodes.

- Query (Value): To get the total count, a node sums all the values in the array: $\sum_{j=0}^{n-1} V[j]$.

- Merge: When two nodes sync, they merge their arrays by taking the maximum value for each index: $V_{merged}[i] = \max(V_{node1}[i], V_{node2}[i])$.

Why it Always Converges

The "magic" of the G-Counter lies in its mathematical properties. For a data type to converge without coordination, its merge operation must satisfy three properties (collectively known as a Join-Semilattice):

- Commutativity: The order of merging doesn't matter ($A \text{ merged with } B$ is the same as $B \text{ merged with } A$).

- Associativity: Grouping doesn't matter ($(A \cup B) \cup C$ is the same as $A \cup (B \cup C)$).

- Idempotency: Merging the same data twice doesn't change the result ($A \cup A = A$).
