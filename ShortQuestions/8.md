**Explain what multi-stage builds are and why they are important. Provide a practical example scenario where multi-stage builds would significantly reduce image size.**

1. What are multi-stage builds

Multi-stage builds are a Docker feature that allows you to use multiple FROM statements in a single Dockerfile, each defining a separate stage of the build process. The key idea is that you can perform heavy build tasks, such as compiling code or installing development dependencies, in an intermediate stage and then copy only the necessary artifacts into the final image. This way, the final image does not include unnecessary build tools or temporary files.

2. Benefits (size reduction, security) 

The primary benefit of multi-stage builds is the significant reduction in image size because only the minimal runtime artifacts are included in the final image. Smaller images are faster to transfer and deploy and consume less storage. Security is also improved, as sensitive build tools or source code do not end up in the production image, reducing the attack surface.

3. Example use case (Java/Maven build)

A common scenario is building a Java application with Maven. In the first stage, you can use a Maven image to compile the Java code and package the application into a JAR file. In the second stage, you use a lightweight OpenJDK runtime image and copy only the generated JAR from the build stage. This avoids including Maven, source code, or unnecessary libraries in the final image, dramatically reducing its size.

4. Impact on deployment

Multi-stage builds make deployment faster and more reliable. Smaller images download and start more quickly, which reduces startup times in containers and minimizes bandwidth usage in CI/CD pipelines. They also make production environments cleaner, containing only what is strictly necessary to run the application. This practice leads to leaner, more secure, and easier-to-maintain containerized applications.
