**In the CAP theorem, why is Partition Tolerance (P) considered mandatory in a real distributed system? Given that P is mandatory, what is the actual trade-off a system designer must make?**

In any real distributed system, network partitions are inevitable due to:

- Hardware failures

- Network outages

- High latency or dropped packets

Even if partitions are rare, a system that cannot tolerate them will fail whenever they occur.


Once we accept that P is a must, CAP reduces to a choice between Consistency (C) and Availability (A):

| Choice        | Meaning                                                                                                                    |
| ------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **CP system** | The system **remains consistent** even if some nodes become unavailable. Some requests might fail during a partition.      |
| **AP system** | The system **remains available** and responds to all requests, but consistency may be **temporarily broken** across nodes. |

Example:

- CP: A bank database that refuses withdrawals if it cannot guarantee up-to-date balances across branches.

- AP: A social media feed that continues accepting posts even if some servers are temporarily out of sync; eventual consistency resolves conflicts later.
