**Docker key concepts**

Docker is a platform for building, packaging, and running applications inside containers. A container is a lightweight, isolated runtime environment that includes the application and all its dependencies (libraries, system tools, runtime). Unlike virtual machines, containers share the host OS kernel, making them faster and more resource-efficient.

A Docker Image is a read-only template used to create containers. It contains application code, runtime, libraries, and configuration. Images are typically built using a Dockerfile, which defines step-by-step instructions (e.g., base image, copying files, installing dependencies). Images are layered, which improves caching and efficiency.

A Docker Container is a running instance of an image. Containers are isolated via Linux namespaces and control groups (cgroups), which provide process isolation, filesystem separation, and resource limits (CPU, memory).

Docker also introduces Docker Registry, such as Docker Hub, where images are stored and distributed. Teams build images once and deploy them consistently across environments (dev, test, prod), solving the classic “works on my machine” problem.
